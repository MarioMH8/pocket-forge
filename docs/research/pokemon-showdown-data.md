## Conclusión

La fuente canónica operativa es el repositorio oficial del servidor [`smogon/pokemon-showdown`](https://github.com/smogon/pokemon-showdown): versiona tablas TypeScript bajo `data/`, más la definición de formatos bajo `config/`. El servidor las carga localmente y de forma perezosa a través de `Dex`; no descarga estas tablas desde una API HTTP durante esa carga ([`sim/dex.ts:8-24`](https://github.com/smogon/pokemon-showdown/blob/c23d2e942c9c0daadb13a7162a385bf78e3c9353/sim/dex.ts#L8-L24), [`sim/dex.ts:447-480`](https://github.com/smogon/pokemon-showdown/blob/c23d2e942c9c0daadb13a7162a385bf78e3c9353/sim/dex.ts#L447-L480)).

El repositorio oficial del navegador, [`smogon/pokemon-showdown-client`](https://github.com/smogon/pokemon-showdown-client), no mantiene otro corpus canónico: genera sus assets `play.pokemonshowdown.com/data/*.js` desde un checkout compilado del servidor; dichos assets están ignorados como productos construidos ([`build-tools/build-indexes:11-35`](https://github.com/smogon/pokemon-showdown-client/blob/f2faebd6892b314d785a0038f77309afed36970c/build-tools/build-indexes#L11-L35), [`.gitignore:15-18`](https://github.com/smogon/pokemon-showdown-client/blob/f2faebd6892b314d785a0038f77309afed36970c/.gitignore#L15-L18)).

## Carga y consumo

1. `Dex` declara las tablas de datos y activa `loadData()` al acceder a `data`; `includeData()` permite precargarlas ([`sim/dex.ts:44-96`](https://github.com/smogon/pokemon-showdown/blob/c23d2e942c9c0daadb13a7162a385bf78e3c9353/sim/dex.ts#L44-L96), [`sim/dex.ts:161-184`](https://github.com/smogon/pokemon-showdown/blob/c23d2e942c9c0daadb13a7162a385bf78e3c9353/sim/dex.ts#L161-L184)). `loadData()` construye rutas bajo el directorio local de datos y usa `require(filePath)` ([`sim/dex.ts:447-463`](https://github.com/smogon/pokemon-showdown/blob/c23d2e942c9c0daadb13a7162a385bf78e3c9353/sim/dex.ts#L447-L463)).
2. Las APIs `Dex.moves` y `Dex.abilities` normalizan aliases, consultan `dex.data` y memoizan la entidad resultante; por tanto la lectura normal del simulador se realiza sobre las tablas cargadas, no contra un servicio remoto ([`sim/dex-moves.ts:612-676`](https://github.com/smogon/pokemon-showdown/blob/c23d2e942c9c0daadb13a7162a385bf78e3c9353/sim/dex-moves.ts#L612-L676), [`sim/dex-abilities.ts:75-115`](https://github.com/smogon/pokemon-showdown/blob/c23d2e942c9c0daadb13a7162a385bf78e3c9353/sim/dex-abilities.ts#L75-L115)).
3. El cliente sí solicita en el navegador `data/pokedex.js`, `moves.js`, `items.js`, `abilities.js` y `typechart.js` como assets del despliegue ([`play.pokemonshowdown.com/index-new.html:124-140`](https://github.com/smogon/pokemon-showdown-client/blob/f2faebd6892b314d785a0038f77309afed36970c/play.pokemonshowdown.com/index-new.html#L124-L140)). Su build los deriva explícitamente de `dist/data/*.js` del servidor y añade los tiers a `BattlePokedex` ([`build-tools/build-indexes:1381-1446`](https://github.com/smogon/pokemon-showdown-client/blob/f2faebd6892b314d785a0038f77309afed36970c/build-tools/build-indexes#L1381-L1446)). En tiempo de ejecución, los consume mediante globales como `BattlePokedex`, `BattleMovedex` y `BattleAbilities` ([`globals.d.ts:30-37`](https://github.com/smogon/pokemon-showdown-client/blob/f2faebd6892b314d785a0038f77309afed36970c/play.pokemonshowdown.com/src/globals.d.ts#L30-L37), [`battle-dex.ts:637-675`](https://github.com/smogon/pokemon-showdown-client/blob/f2faebd6892b314d785a0038f77309afed36970c/play.pokemonshowdown.com/src/battle-dex.ts#L637-L675)).

## Implicación práctica

Para una integración reproducible, fijar un commit de `smogon/pokemon-showdown` y resolver el mod/generación con `Dex.mod(...)` o `Dex.forFormat(...)`. No basta con `pokedex.ts`: la legalidad requiere especie + learnset + generación/mod + reglas del formato; el juego competitivo añade `formats-data.ts`, `config/formats.ts` y `rulesets.ts`. Los assets vivos de `play.pokemonshowdown.com/data/` son útiles para el cliente, pero son salidas generadas y no la fuente Git autoritativa.
